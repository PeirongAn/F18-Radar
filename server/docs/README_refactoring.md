# 雷达系统服务器重构说明

## 重构目标

将原本1336行的 `radar_server.py` 按照单一职责原则拆分为多个模块，提高代码的可维护性、可测试性和可扩展性。

## 新架构设计

### 模块划分

| 模块 | 文件 | 职责 | 行数 |
|------|------|------|------|
| 配置管理 | `config_manager.py` | 加载和管理系统配置 | ~60 |
| 数据库管理 | `database_manager.py` | 数据库连接、初始化和异步写入 | ~250 |
| 任务管理 | `task_manager.py` | 管理用户任务进度和场景 | ~180 |
| 目标管理 | `target_manager.py` | 雷达目标生成、更新和威胁评估 | ~200 |
| 威胁管理 | `threat_manager.py` | SA威胁生成和紧急事件处理 | ~120 |
| 消息处理 | `message_handler.py` | 处理客户端消息和业务逻辑 | ~440 |
| WebSocket服务 | `websocket_server.py` | WebSocket连接和消息传输 | ~90 |
| 主入口 | `main.py` | 系统初始化和启动 | ~50 |

### 设计模式应用

1. **单一职责原则 (SRP)**
   - 每个模块只负责一个特定的功能领域
   - 降低模块间的耦合度

2. **依赖注入**
   - 通过导入机制实现模块间的依赖关系
   - 便于单元测试和模块替换

3. **工厂模式**
   - 各管理器类负责创建和管理相应的对象实例

4. **观察者模式**
   - WebSocket服务器监听客户端消息
   - 消息处理器根据消息类型路由到相应处理方法

## 模块详细说明

### ConfigManager (配置管理)
- **职责**: 加载 `agent_level.json` 配置文件
- **功能**: 
  - 配置文件解析
  - 默认配置fallback
  - 配置项访问接口
- **单例模式**: `config_manager` 全局实例

### DatabaseManager (数据库管理)
- **职责**: 数据库操作的统一管理
- **功能**:
  - 异步写入队列
  - 数据库连接池管理
  - 表结构初始化和升级
  - 练习模式数据隔离
- **线程安全**: 使用WAL模式和专用写入线程

### TaskScenarioManager (任务管理)
- **职责**: 用户任务进度的持久化管理
- **功能**:
  - 任务队列生成和管理
  - 进度保存和恢复
  - AI/手动模式切换
  - 练习/正式模式区分
- **数据持久化**: 与数据库紧密集成

### TargetManager (目标管理)
- **职责**: 雷达目标的生命周期管理
- **功能**:
  - 目标生成和初始化
  - 实时位置更新
  - 威胁评估算法
  - 雷达数据格式化
- **算法封装**: 威胁评估逻辑独立可配置

### ThreatManager (威胁管理)
- **职责**: SA页面威胁相关功能
- **功能**:
  - 威胁类型生成
  - 紧急事件模拟
  - 自动事件推送
- **事件驱动**: 支持异步事件处理

### MessageHandler (消息处理)
- **职责**: 客户端消息的业务逻辑处理
- **功能**:
  - 消息类型路由
  - 业务流程控制
  - 状态管理
  - 响应生成
- **路由机制**: 基于消息类型的方法分发

### WebSocketServer (WebSocket服务)
- **职责**: 网络通信层
- **功能**:
  - 连接管理
  - 消息收发
  - 会话状态维护
- **协议无关**: 与业务逻辑解耦

## 启动方式

### 新方式 (推荐)
```bash
cd server
python main.py
```

### 原方式 (仍可用)
```bash
cd server
python radar_server.py
```

## 兼容性

- ✅ **完全向后兼容**: 客户端无需任何修改
- ✅ **API不变**: 所有WebSocket消息格式保持一致
- ✅ **数据库兼容**: 使用相同的数据库结构
- ✅ **配置兼容**: 使用相同的配置文件

## 优势

### 开发效率
- **模块独立**: 可以并行开发不同模块
- **测试友好**: 每个模块可以独立进行单元测试
- **调试简化**: 问题定位更加精确

### 维护性
- **代码组织**: 相关功能集中在同一模块
- **修改影响**: 修改某个功能不会影响其他模块
- **文档清晰**: 每个模块职责明确

### 扩展性
- **新功能**: 可以轻松添加新的管理器模块
- **功能替换**: 可以替换某个模块而不影响其他部分
- **配置灵活**: 支持不同的部署配置

## 性能影响

- **内存使用**: 略有增加（模块导入开销）
- **执行效率**: 基本无影响（函数调用开销可忽略）
- **启动时间**: 略有增加（模块初始化）
- **整体**: 性能影响微乎其微，可维护性大幅提升
