# Eye Gaze Data Dictionary and Threat Ranking Statistics

This document describes the gaze data generated by this repository and the
recommended method for calculating gaze metrics for the threat ranking task.

## Storage Layout

Gaze data is stored under `server/data/gaze/`.

```text
server/data/gaze/
  gaze_records.db
  users/
    {user_id}/
      {YYYYMMDD}/
        {task_id}/
          raw_gaze.jsonl
          summary.json
```

`gaze_records.db` is the index and event database. `raw_gaze.jsonl` is the
per-frame gaze stream for one task. `summary.json` is a task-level summary
written when a gaze task ends.

The normal join key is `task_id`.

## Time Units

Most gaze timestamps are Unix-like microseconds:

- `start_time_us`, `end_time_us`
- `appear_time_us`, `disappear_time_us`
- `raw_gaze.jsonl` field `ts_us`

Operation records in `server/data/radar_operations.db` use milliseconds:

- `user_operations.timestamp`
- `user_operations.receive_timestamp`

Convert carefully when joining these two databases.

## `gaze_records.db`

### `gaze_tasks`

One row represents one gaze-tracked task lifecycle.

| Field | Meaning |
| --- | --- |
| `id` | SQLite row id. |
| `task_id` | Repository task id. Main key used to join gaze tables, raw files, and operation records. |
| `user_id` | User who ran the task. |
| `task_source` | Source or owner of the task, usually `manual` or `AI`. |
| `task_name` | Task type. Threat ranking tasks use `SA_THREAT_RESPONSE`; radar target tasks use `RADAR_TARGETING`. |
| `data_dir` | Absolute path to the task directory containing `raw_gaze.jsonl` and `summary.json`. |
| `start_time_us` | Gaze task start time, in microseconds. |
| `end_time_us` | Gaze task end time, in microseconds. `NULL` means the gaze task is still active or was not closed. |
| `start_trigger` | Code-level reason for starting the gaze task, for example `task_start`. |
| `end_trigger` | Code-level reason for ending the gaze task, for example `task_result_confirmed`. |
| `duration_ms` | Task duration in milliseconds. |
| `total_frames` | Number of gaze frames recorded for this task. |
| `valid_frames` | Number of frames with a valid gaze point. |
| `in_region_frames` | Number of frames where the gaze point hit the current attention region. |
| `status` | `active` or `completed`. |
| `created_at` | SQLite insert timestamp. |

Important: `gaze_tasks.start_time_us` and `gaze_tasks.end_time_us` are task
lifecycle timestamps. They are not the target appearance/disappearance times.

### `gaze_targets`

One row represents one attention-region visibility window. For threat ranking
statistics, this table is the source of "target appeared" and "target
disappeared" times.

| Field | Meaning |
| --- | --- |
| `id` | SQLite row id. |
| `task_id` | Task id. References `gaze_tasks.task_id`. |
| `bbox_json` | Raw region payload received from the frontend, stored as JSON text. |
| `normalized_bbox_json` | Regions normalized by the gaze service, stored as JSON text. |
| `screen_width` | Screen width used during coordinate normalization. |
| `screen_height` | Screen height used during coordinate normalization. |
| `appear_time_us` | Time when the attention region became visible, in microseconds. |
| `disappear_time_us` | Time when the attention region was cleared, in microseconds. `NULL` means it has not been cleared. |
| `auto_closed` | `1` if the service closed the region automatically when the task ended; otherwise `0`. |
| `created_at` | SQLite insert timestamp. |

For a closed window:

```text
target_visible_ms = (disappear_time_us - appear_time_us) / 1000
```

If `disappear_time_us` is `NULL`, use `gaze_tasks.end_time_us` only when the
task is completed and an approximate closed window is acceptable. Otherwise
skip the row.

### `gaze_feedback_events`

One row represents a low-frequency attention feedback event, such as an
out-of-box reminder.

| Field | Meaning |
| --- | --- |
| `id` | SQLite row id. |
| `task_id` | Task id. References `gaze_tasks.task_id`. |
| `event_time_ms` | Feedback event time in milliseconds. |
| `reason` | Feedback reason, for example `consecutive_out_of_box_false`. |
| `consecutive_false_count` | Number of consecutive invalid or out-of-region frames that triggered feedback. |
| `threshold` | Threshold used by the service. |
| `payload_json` | Full feedback payload as JSON text. |
| `created_at` | SQLite insert timestamp. |

This table is useful for attention-reminder analysis, but it is not the primary
source for target visibility or gaze dwell time.

## `raw_gaze.jsonl`

Each line is one analysis frame.

```json
{"ts_us":1779250000000000,"task_id":"1","user_id":"anpeirong","gaze":[0.421,0.913],"valid":true,"in_region":true,"region_hits":["region_1"]}
```

| Field | Meaning |
| --- | --- |
| `ts_us` | Frame timestamp in microseconds. |
| `task_id` | Task id. |
| `user_id` | User id. |
| `gaze` | Gaze point as `[x, y]`. `null` when invalid. Coordinate interpretation follows the gaze service output. |
| `valid` | `true` when the gaze point is valid. |
| `in_region` | `true` when this frame hits the active attention region. |
| `region_hits` | List of hit region ids. Empty when no region is hit. |

Invalid gaze is stored as `gaze: null`, `valid: false`, `in_region: false`.

## `summary.json`

`summary.json` repeats the final task-level summary:

| Field | Meaning |
| --- | --- |
| `task_id` | Task id. |
| `user_id` | User id. |
| `task_source` | Task source or owner. |
| `task_name` | Task type. |
| `data_dir` | Task data directory. |
| `start_us` | Task start time in microseconds. |
| `end_us` | Task end time in microseconds. |
| `duration_ms` | Task duration in milliseconds. |
| `total_frames` | Total recorded frames. |
| `valid_frames` | Valid gaze frames. |
| `in_region_frames` | Frames that hit the attention region. |
| `feedback_count` | Number of feedback events generated during the task. |
| `status` | Task status. |

Use `gaze_records.db` as the authoritative index. Use `summary.json` as a
per-task file-level check.

## `radar_operations.db`

Threat ranking statistics often need task metadata or selected threat details.
Those live in `server/data/radar_operations.db`.

### `task_settings`

Relevant fields:

| Field | Meaning |
| --- | --- |
| `task_id` | Task id. |
| `user_id` | User id. |
| `task_type` | Task type. Threat ranking uses `SA_THREAT_RESPONSE`. |
| `event_owner` | `manual` or `AI`. |
| `repetition_count` | Repetition count for this scenario. |
| `is_ai_active` | Whether AI assistance was active. |
| `ai_level_name` | AI level name. |
| `difficulty_name` | Difficulty name. |
| `audio_enabled` | Whether audio was enabled. |

### `user_operations`

Relevant threat ranking operation types:

| Operation | Meaning |
| --- | --- |
| `SwitchSA` | User entered or started an SA threat ranking task. |
| `ResetSA` | User reset or started the next SA threat ranking task. |
| `threat_clicked` | A threat item was selected. `parameters` contains selected threat details. |

For `threat_clicked`, `parameters` is JSON text and commonly includes:

| Parameter | Meaning |
| --- | --- |
| `threat_id` | Selected threat id. |
| `label` | Threat display label. |
| `priority` | Recorded priority label. |
| `is_highest_priority` | Whether this selection matched the highest-priority threat. |
| `is_correct` | Correctness flag, usually same as `is_highest_priority`. |

## Threat Ranking Gaze Metrics

Use `gaze_targets` rows joined to `gaze_tasks` where
`gaze_tasks.task_name = 'SA_THREAT_RESPONSE'`.

For each attention-region window:

```text
window_start_us = gaze_targets.appear_time_us
window_end_us   = gaze_targets.disappear_time_us
target_visible_ms = (window_end_us - window_start_us) / 1000
```

Then read the task's `raw_gaze.jsonl` and keep frames whose time interval
overlaps the target window. A frame contributes to look time only when:

```text
valid == true AND in_region == true
```

Recommended dwell-time calculation:

1. Sort raw frames by `ts_us`.
2. Treat each frame as active until the next frame timestamp.
3. Clip each frame interval to `[window_start_us, window_end_us]`.
4. Add the clipped interval only for frames where `valid` and `in_region` are both true.
5. Cap unusually large frame gaps to avoid inflating dwell time after a dropped stream segment.

Result fields:

| Field | Meaning |
| --- | --- |
| `target_visible_ms` | Time from target appearance to disappearance. |
| `look_at_target_ms` | Estimated time the user's valid gaze hit the target region. |
| `look_ratio` | `look_at_target_ms / target_visible_ms`. |
| `valid_frame_count` | Valid frames inside the target window. |
| `in_region_frame_count` | Hit frames inside the target window. |
| `feedback_count` | Number of attention feedback events during the same target window. |

## Script

Use `server/statistics/threat_gaze_statistics.py`:

```powershell
python server\statistics\threat_gaze_statistics.py
```

Write CSV:

```powershell
python server\statistics\threat_gaze_statistics.py --output server\data\gaze\threat_gaze_statistics.csv
```

Limit by user or task:

```powershell
python server\statistics\threat_gaze_statistics.py --user-id zhaomiyao17
python server\statistics\threat_gaze_statistics.py --task-id 62
```

Include currently active or unclosed target windows:

```powershell
python server\statistics\threat_gaze_statistics.py --include-open
```

By default the script skips unclosed windows, reads
`server/data/gaze/gaze_records.db`, optionally joins
`server/data/radar_operations.db` when present, and prints CSV to stdout.
