# 眼动数据字典与威胁排序统计说明

本文说明本项目生成的眼动数据、各字段含义，以及威胁排序任务中眼动指标的推荐计算方法。

## 存储结构

眼动数据存放在 `server/data/gaze/` 下：

```text
server/data/gaze/
  gaze_records.db
  raw/
    {user_id}/
      {task_id}/
        raw_gaze.jsonl
```

- `gaze_records.db`：任务索引和事件数据库。
- `raw_gaze.jsonl`：单个任务的逐帧原始眼动数据流。
- 新任务目录不再生成 `summary.json`；任务摘要应从 `gaze_tasks` 表还原。

各类数据通常通过 `task_id` 关联。

## 时间单位

眼动数据中的大部分时间戳使用微秒：

- `start_time_us`、`end_time_us`
- `appear_time_us`、`disappear_time_us`
- `raw_gaze.jsonl` 中的 `ts_us`

`server/data/radar_operations.db` 中的操作记录使用毫秒：

- `user_operations.timestamp`
- `user_operations.receive_timestamp`

关联两个数据库时必须先统一时间单位。

## `gaze_records.db`

### `gaze_tasks`

每行表示一个眼动任务的完整生命周期。

| 字段 | 含义 |
| --- | --- |
| `id` | SQLite 行号。 |
| `task_id` | 项目任务 ID，是关联眼动表、raw 文件和操作记录的主要键。 |
| `user_id` | 执行任务的用户。 |
| `task_source` | 任务来源或执行方，通常为 `manual` 或 `AI`。 |
| `task_name` | 任务类型。威胁排序为 `SA_THREAT_RESPONSE`，雷达目标任务为 `RADAR_TARGETING`。 |
| `data_dir` | 包含 `raw_gaze.jsonl` 的任务目录绝对路径。 |
| `start_time_us` | 眼动任务开始时间，单位为微秒。 |
| `end_time_us` | 眼动任务结束时间，单位为微秒；`NULL` 表示任务仍在进行或未正常关闭。 |
| `start_trigger` | 启动眼动任务的代码触发原因，例如 `task_start`。 |
| `end_trigger` | 结束眼动任务的代码触发原因，例如 `task_result_confirmed`。 |
| `duration_ms` | 任务持续时间，单位为毫秒。 |
| `total_frames` | 该任务记录的眼动总帧数。 |
| `valid_frames` | 注视点有效的帧数。 |
| `in_region_frames` | 注视点命中当前注意区域的帧数。 |
| `status` | 任务状态：`active` 或 `completed`。 |
| `created_at` | SQLite 记录写入时间。 |

注意：`gaze_tasks.start_time_us` 和 `gaze_tasks.end_time_us` 是任务生命周期时间，不是目标出现和消失时间。

### `gaze_targets`

每行表示一个注意区域的可见时间窗口。统计威胁排序任务时，应使用该表确定“目标出现”和“目标消失”的时间。

| 字段 | 含义 |
| --- | --- |
| `id` | SQLite 行号。 |
| `task_id` | 任务 ID，关联 `gaze_tasks.task_id`。 |
| `bbox_json` | 前端传入的原始区域数据，以 JSON 文本保存。 |
| `normalized_bbox_json` | 眼动服务归一化后的区域，以 JSON 文本保存。 |
| `screen_width` | 坐标归一化时使用的屏幕宽度。 |
| `screen_height` | 坐标归一化时使用的屏幕高度。 |
| `appear_time_us` | 注意区域显示时间，单位为微秒。 |
| `disappear_time_us` | 注意区域清除时间，单位为微秒；`NULL` 表示尚未清除。 |
| `auto_closed` | 任务结束时由服务自动关闭区域则为 `1`，否则为 `0`。 |
| `created_at` | SQLite 记录写入时间。 |

已关闭窗口的可见时长计算方式：

```text
target_visible_ms = (disappear_time_us - appear_time_us) / 1000
```

如果 `disappear_time_us` 为 `NULL`，只有在任务已完成且允许使用近似结束时间时，才可用 `gaze_tasks.end_time_us` 代替；否则应跳过该记录。

### `gaze_feedback_events`

每行表示一次低频注意力反馈事件，例如持续未注视目标区域时的提醒。

| 字段 | 含义 |
| --- | --- |
| `id` | SQLite 行号。 |
| `task_id` | 任务 ID，关联 `gaze_tasks.task_id`。 |
| `event_time_ms` | 反馈事件时间，单位为毫秒。 |
| `reason` | 反馈原因，例如 `consecutive_out_of_box_false`。 |
| `consecutive_false_count` | 触发反馈前连续无效或未命中区域的帧数。 |
| `threshold` | 服务使用的触发阈值。 |
| `payload_json` | 完整反馈消息，以 JSON 文本保存。 |
| `created_at` | SQLite 记录写入时间。 |

该表适合分析注意力提醒，但不是计算目标可见时间或注视时长的主要数据源。

## `raw_gaze.jsonl`

文件每行是一帧分析数据。精简示例：

```json
{"ts_us":1779250000000000,"gaze":[0.421,0.913],"hit":true,"hits":["region_1"]}
```

| 字段 | 含义 |
| --- | --- |
| `ts_us` | 服务收到该帧时生成的时间戳，单位为微秒。 |
| `gaze` | 合并后的注视点 `[x, y]`；无效时为 `null`。坐标含义遵循眼动服务的输出坐标系。 |
| `hit` | 该帧是否命中当前活动注意区域。 |
| `hits` | 命中的区域 ID 列表；未命中时省略。 |
| `device_ts_us` | Tobii 眼动仪内部时钟时间戳。 |
| `sdk_system_ts_us` | Tobii SDK 与计算机时钟同步后的时间戳。 |
| `left_eye`、`right_eye` | Tobii SDK 提供的左右眼独立测量数据。 |

`left_eye` 和 `right_eye` 中的字段：

| 字段 | 含义 |
| --- | --- |
| `gaze_display` | 单眼在显示区域上的归一化二维注视点。 |
| `gaze_user_mm` | 用户坐标系中的单眼三维注视点。 |
| `pupil_diameter_mm` | 估算的瞳孔直径，单位为毫米。 |
| `origin_user_mm` | 用户坐标系中的三维视线起点，可用于分析眼位变化。 |
| `origin_trackbox` | 追踪盒坐标系中的归一化三维视线起点。 |
| `gaze_valid` | 单眼注视点是否有效。 |
| `pupil_valid` | 瞳孔直径是否有效。 |
| `origin_valid` | 视线起点是否有效。 |

完整帧示例：

```json
{
  "ts_us": 1779250000000000,
  "gaze": [0.421, 0.913],
  "hit": true,
  "hits": ["region_1"],
  "device_ts_us": 5321000,
  "sdk_system_ts_us": 1779250000000100,
  "left_eye": {
    "gaze_display": [0.420, 0.912],
    "gaze_user_mm": [12.5, 31.2, 601.4],
    "gaze_valid": true,
    "pupil_diameter_mm": 3.21,
    "pupil_valid": true,
    "origin_user_mm": [-31.0, 18.2, 603.5],
    "origin_trackbox": [0.42, 0.51, 0.63],
    "origin_valid": true
  },
  "right_eye": {
    "gaze_display": [0.422, 0.914],
    "gaze_user_mm": [13.1, 30.8, 600.9],
    "gaze_valid": true,
    "pupil_diameter_mm": 3.18,
    "pupil_valid": true,
    "origin_user_mm": [31.4, 18.0, 603.2],
    "origin_trackbox": [0.58, 0.51, 0.63],
    "origin_valid": true
  }
}
```

说明：

- 无效的合并注视点保存为 `"gaze": null`，同时 `hit` 为 `false`。
- SDK 返回的无效或不支持的数值保存为标准 JSON `null`。
- 眼部图像和外部 TTL 信号属于独立数据流，并依赖具体设备能力；当前 `raw_gaze.jsonl` 不记录这两类数据。

## 任务摘要

应以 `gaze_records.db` 作为任务索引的权威数据源。新任务目录不生成 `summary.json`，任务级摘要字段保存在 `gaze_tasks` 表中。

## `radar_operations.db`

威胁排序统计通常还需要任务元数据或用户选择的威胁详情，这些数据保存在 `server/data/radar_operations.db`。

### `task_settings`

相关字段如下：

| 字段 | 含义 |
| --- | --- |
| `task_id` | 任务 ID。 |
| `user_id` | 用户 ID。 |
| `task_type` | 任务类型；威胁排序使用 `SA_THREAT_RESPONSE`。 |
| `event_owner` | 执行方：`manual` 或 `AI`。 |
| `repetition_count` | 当前场景的重复次数。 |
| `is_ai_active` | 是否启用 AI 辅助。 |
| `ai_level_name` | AI 等级名称。 |
| `difficulty_name` | 难度名称。 |
| `audio_enabled` | 是否启用音频。 |
| `trust_state` | 该任务从 `trust_calibration.state` 保存的信任界面状态；Radar 使用 `sensor`，SA 使用 `threat`。 |

### `user_operations`

威胁排序相关的操作类型：

| 操作 | 含义 |
| --- | --- |
| `SwitchSA` | 用户进入或开始 SA 威胁排序任务。 |
| `ResetSA` | 用户重置或开始下一个 SA 威胁排序任务。 |
| `threat_clicked` | 用户选择了一个威胁项，`parameters` 保存所选威胁详情。 |

`threat_clicked` 的 `parameters` 是 JSON 文本，通常包含：

| 参数 | 含义 |
| --- | --- |
| `threat_id` | 威胁 ID。 |
| `label` | 威胁显示名称。 |
| `priority` | 记录的优先级标签。 |
| `is_highest_priority` | 本次选择是否为最高优先级威胁。 |
| `is_correct` | 是否选择正确，通常与 `is_highest_priority` 一致。 |

## 威胁排序眼动指标

先筛选 `gaze_tasks.task_name = 'SA_THREAT_RESPONSE'`，再通过 `task_id` 关联 `gaze_targets`。

对每个注意区域窗口：

```text
window_start_us = gaze_targets.appear_time_us
window_end_us   = gaze_targets.disappear_time_us
target_visible_ms = (window_end_us - window_start_us) / 1000
```

随后读取该任务的 `raw_gaze.jsonl`，保留时间区间与目标窗口重叠的帧。只有满足以下条件的帧才计入目标注视时间：

```text
gaze != null AND hit == true
```

推荐的注视时长计算方法：

1. 按 `ts_us` 对 raw 帧排序。
2. 将每帧视为持续到下一帧时间戳。
3. 将每帧时间区间裁剪到 `[window_start_us, window_end_us]`。
4. 仅累计 `gaze` 不为 `null` 且 `hit` 为 `true` 的裁剪后区间。
5. 对异常大的帧间隔设置上限，避免数据流中断后夸大注视时长。

结果字段：

| 字段 | 含义 |
| --- | --- |
| `target_visible_ms` | 目标从出现到消失的时长。 |
| `look_at_target_ms` | 有效注视点命中目标区域的估算时长。 |
| `look_ratio` | 注视比例：`look_at_target_ms / target_visible_ms`。 |
| `valid_frame_count` | 目标窗口内的有效注视帧数。 |
| `in_region_frame_count` | 目标窗口内命中区域的帧数。 |
| `feedback_count` | 同一目标窗口内发生的注意力反馈次数。 |

## 统计脚本

运行 `server/statistics/threat_gaze_statistics.py`：

```powershell
python server\statistics\threat_gaze_statistics.py
```

输出 CSV 文件：

```powershell
python server\statistics\threat_gaze_statistics.py --output server\data\gaze\threat_gaze_statistics.csv
```

按用户或任务筛选：

```powershell
python server\statistics\threat_gaze_statistics.py --user-id zhaomiyao17
python server\statistics\threat_gaze_statistics.py --task-id 62
```

包含仍处于活动状态或尚未关闭的目标窗口：

```powershell
python server\statistics\threat_gaze_statistics.py --include-open
```

默认情况下，脚本会：

- 跳过尚未关闭的目标窗口；
- 读取 `server/data/gaze/gaze_records.db`；
- 如果存在 `server/data/radar_operations.db`，则关联其中的数据；
- 将 CSV 输出到标准输出。
