# 信任调控 V1

点击主界面顶部「信任调控设置」，选择信任倾向，分别配置信息内容和高亮区域。保存成功后自动关闭，立即更新当前界面，并同步已连接页面。取消不保存；重新打开会读取后端文件。无连接或保存失败时保留面板和草稿。

配置文件为 `CONFIG_DIR/trust_control_v1.json`（开发环境 `public/trust_control_v1.json`）。其中 `tendency` 是当前倾向，`policies` 保存三种倾向的策略。策略不按任务类型分组，雷达和SA分别渲染本任务的真实观测。正常策略默认不新增内容、不高亮。

内容开关控制补充观测依据和可靠性说明；形式选项只强调已有区域。二者都启用时标记联合调控。当前文件倾向不会被历史行为标签覆盖。

后端仍按用户和任务组缓存快照；通过设置页面成功保存时清除旧策略快照、更新任务启动响应缓存并下发即时策略，当前组和后续任务均使用新配置。直接编辑文件仍在新组读取。快照仅保存在服务进程内，V1不增加数据库表。

配置文件损坏或缺失时作业界面降级为基础显示，后端记录原因；设置页面报告读取失败。先修复配置文件再重新打开设置。保存采用同目录临时文件替换，失败不覆盖旧文件。

## 手工验收

1. 打开设置，确认顶部只有信任倾向，默认正常。
2. 选择欠信任，启用补充观测，选择观测高亮，保存；重新打开确认值保留。
3. 启动一组雷达任务，确认补充观测与青色强调，并正常选择、确认。
4. 本组内保存过信任策略：关闭补充观测，打开可靠性说明，选择可靠性高亮；保存后立即显示可靠性说明和琥珀色强调，补充观测消失。
5. 下一次任务及重连继续使用已保存策略。取消草稿修改，重新打开仍为已保存值。
6. 分别验证仅内容、仅高亮、联合和基础四类：仅高亮不得增加补充说明。
7. 同一策略用于SA，补充依据应展示威胁类别等SA观测，而非雷达单位。
8. 断开后端后保存，确认报错并保留草稿，不误报成功；重新连接并打开核对配置。
9. 恢复正常策略，当前界面立即恢复基础显示；任务确认、问卷与采集流程保持正常。

功能验收不代表已达到70%的心理信任调控成功率。
