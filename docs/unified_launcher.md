# 统一启动与调控配置窗口

双击项目根目录 `Start-Unified.cmd`。需要 Windows 和包含 Tkinter 的 Python 3；窗口不依赖 Server 运行。

## 使用

1. 每种模式分别配置 Server 和前端脚本，共四个独立路径，可使用 `.cmd`、`.bat`、`.ps1`、`.exe`。窗口只展示当前模式的两个路径，切换模式保留草稿。
2. 正常模式先创建正常版 Server 进程，再创建正常版前端进程。
3. 调控模式指定配置目录，选择欠信任或过信任并编辑策略。切换倾向会保留另一套草稿；所选倾向作为启动时的信任状态。
4. “保存配置”只写文件；“保存配置并启动”先写文件再依次启动调控版 Server 和前端。“关闭”按钮和右上角关闭按钮都会终止本窗口启动的 Server 进程树，然后关闭窗口，不写未保存的修改。启动失败在窗口显示原因，两端输出分别追加至根目录 `launcher-server.log` 和 `launcher-frontend.log`。

启动前校验当前模式的两个路径，任一个无效都不会启动。创建 Server 进程后等待 1.2 秒检查是否立即失败；失败则不启动前端。该等待不是服务就绪检测，前端脚本需要自行等待服务可用或支持连接重试。前端启动失败时保留 Server 并提示部分启动状态，不自动终止进程。程序以各自脚本所在目录为工作目录，启动过程不弹出额外终端；脚本应无需交互输入，PowerShell 使用现有执行策略。

## 配置位置与接入

- 根目录 `launcher_settings.json`：`normal_server_script`、`normal_frontend_script`、`control_server_script`、`control_frontend_script` 四个路径，以及启动模式、调控配置目录。旧版总入口字段保留，但不自动当作 Server 脚本执行；首次升级需重新选择。
- 所选目录的 `trust_control_v1.json`：当前倾向、欠信任与过信任显示策略。默认目录为本项目 `public`。
- 当前后端格式仍要求 `normal`，启动器将其固定为基础显示且不提供编辑项。
- 配置目录通过环境变量 `F18_RADAR_CONFIG_DIR` 传递给调控脚本及其子进程。调控脚本须保留该变量。仓库中的便携启动脚本已支持保留外部传入值。
- 该目录也是当前 Server 的其他配置来源，请选择本套系统已有的完整配置目录。便携版通常为其 `web` 目录。单独把调控 JSON 写入空目录可能导致其他配置无法读取。
- 外部 UE/ViSim 程序必须已实现策略读取或接收 Server 下发；启动器只负责生成配置和启动程序，不会自动赋予外部程序调控能力。

脚本执行结束不代表服务就绪；窗口只报告创建进程、退出码及日志位置。同一窗口在入口进程或受管理的 Server 子进程仍运行时会阻止重复启动。

## 关闭时清理 Server

Server 使用独立的 Windows Job Object 管理。启动辅助进程先等待，加入进程组成功后才执行脚本，避免快速启动的子进程漏出管理范围。即使入口脚本先退出，关闭统一启动窗口仍会终止剩余 Server 子进程。该机制也会在启动器进程异常退出、句柄被系统回收时清理 Server。

此处是强制终止进程树，结束采集与保存实验数据后再关闭启动器。单独启动的前端不在 Server 进程组中，不随此操作终止。通过已有系统服务、计划任务或另一个既有进程代为启动的服务不属于此进程树，不能由该机制管理。升级前已残留的进程也不会自动接管。

机制依据：[Microsoft Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。
